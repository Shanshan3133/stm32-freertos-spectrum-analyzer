# 软件完成进度

## 已完成并在电脑端验证

- 1024 点 FFT 参考实现、Hann 窗、RMS、峰值和主频插值；C 单元测试已编写并通过 ARM 严格编译检查，本机缺少原生 C 工具链，尚未执行该二进制测试。
- 双通道频谱结果模型以及 128 点时域预览。
- 二进制协议 v2、CRC-16、转义、序号丢失统计和损坏帧重同步。
- 8 位频谱传输压缩，使 20 Hz 双通道输出满足 921600 baud 最坏带宽。
- Python 串口解码、频谱分块重组、实时绘图、CSV 记录和自检。
- TIM5 1 MHz 长时间基准，避免 180 MHz DWT 大约 23.9 秒回绕造成误报。
- DMA generation 复制前后检查，过期半缓冲不会进入 FFT 结果。
- 弱信号、ADC 削顶和冻结输入的独立健康标志。
- 摘要、完整 512 点频谱、128 点波形三类 CSV 输出。
- 21 项 Python 测试；便携 C 文件通过 Cortex-M4 GCC 严格警告编译，并由 GitHub Actions 在 Linux 上实际构建运行。
- 主机重组缓存限制为 16 个未完成频谱，持续丢包不会导致内存无限增长；同时检测重复、乱序和元数据不一致的数据块。
- 看门狗只接受真实数据处理进展；DMA 或队列超时不再被错误地当作健康投票。
- 可编译启用的采集丢包、ADC 冻结、UART 失败和 DSP 卡死故障注入。
- 明确并实现处理顺序：逐块去直流均值，然后施加 Hann 窗，最后 FFT。
- 发布 12 组浮点与 Q15 定点模型误差对比；实际 CMSIS-DSP 结果仍待上板。
- 明确状态恢复策略：信号质量位逐帧恢复，DMA/UART/丢包故障保持到复位。
- DSP 使用 DWT 周期差测量执行时间，再换算为每帧 `processing_us`。

## 已在 NUCLEO-F446RE 上运行

- ADC1/ADC2 双重规则同步模式的 DMA 循环双缓冲接口。
- FreeRTOS 采集、DSP、遥测、看门狗四任务和固定优先级。
- CMSIS-DSP Q15 FFT 后端。
- DAC1 DMA 产生 976.5625 Hz 回环测试信号。
- USART2 TX DMA，经板载 ST-LINK 虚拟串口传到电脑。
- 数据连续性、DSP deadline、UART 背压和看门狗健康投票。
- 空闲时执行 `WFI`。
- 使用官方 STM32CubeF4 依赖构建目标固件，烧录并读回校验通过。
- 2026-09-27 无接线串口连续运行 60 秒，两路共 2387 个完整频谱，CRC/序号错误与固件报告丢块均为 0。
- DSP 故意暂停的专用测试固件触发 IWDG 复位，并报告看门狗复位标志；测试后已恢复正常固件。
- 2026-09-28 将 A2/PA4、A0/PA0、A1/PA1 用三根公对公线接入面包板同一组相通孔，运行 60 秒：两路全部 2387 帧均在 FFT 第 10 个频点检测到测试信号，协议错误及报告丢块为 0。
- 同一接线下完成 1800.071 秒持续测试：两路分别收到 35998/35999 帧，全部检出第 10 个频点，CRC、格式、序号、报告丢块和 9 ms DSP 截止时间超限均为 0；本次观测的处理时间最大值为 1742 微秒，p99.9 为 1731 微秒。
- 专用 ADC 冻结注入固件的 205 帧全部报告弱信号、冻结和人工注入，并清除信号有效位；测试后刷回正常固件，10 秒回环复查通过。
- 已保存硬件照片、实测波形与频谱图、完整 512 频点 CSV、30 分钟原始终端输出。见 [测试记录](../evidence/run-20260928/additional-validation.md)。
